# MCTSv8 VPW Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an isolated `mctsv8_vpw` method with depth-dependent 8/5/3 maximum width, two-phase batched diversity generation, and score-gated reserve visibility.

**Architecture:** Keep legacy `mctsv8` search code untouched.  The new method owns a small pure stage policy, a vLLM batch-generation adapter, and an MCTS/node implementation whose hidden reserve pool is invisible until `0.5 * original + 0.5 * Q/N > 0.8`; opened nodes enter the same upcoming prior-aware UCT comparison with their own reward.

**Tech Stack:** Python 3.10, Hydra/OmegaConf, vLLM, pytest, existing VReST MCTSv8 reward and answer-extraction helpers.

**Spec:** `docs/superpowers/specs/2026-11-05-mctsv8-vpw-design.md`

## Global Constraints

- Preserve `mctsv8_a`, `mctsv8_b`, and `mctsv8_c` behavior and dispatch.
- New method name is exactly `mctsv8_vpw`.
- Do not add embedding similarity or P3Pro in this version.
- Root activation-original score is `1.0` but root MCTS reward remains unchanged.
- Three diversity prompts are generated in one real vLLM scheduler call and all parsed candidates use batched reward scoring.
- Hidden reserve children must not appear in UCT, traversal, backpropagation, or final voting until opened.
- The remote worktree is already dirty; do not commit, reset, or overwrite unrelated changes.  Use backups, per-file hashes, and test checkpoints instead.

## Review Focus

- `max_depth <= 1`: progress must remain finite and terminal-safe; Task 1 pins it.
- Candidate parsing yields fewer than requested nodes: return up to the valid count without placeholder children; Task 2 pins it.
- `N(parent) == 0`: no division and no reserve opening; Task 3 pins it.
- Empty/exhausted reserve pool: repeated selection must be idempotent; Task 3 pins it.
- Pickle resume: immutable activation metadata and visible/reserve separation survive serialization; Task 3 pins it.
